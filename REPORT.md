# Отчёт по задаче «Обедающие философы»

Исполнитель: Пичурин Никита

Группа: БПИ253

Вариант: 5

## Задача

За круглым столом сидят несколько философов. Каждый сначала размышляет, затем пытается поесть. Между соседними философами лежит одна вилка, а для еды нужны две. После еды философ освобождает обе вилки и начинает следующий цикл.

Нужно организовать выдачу вилок так, чтобы не возникала взаимная блокировка, и следить за временем ожидания. Количество философов, число циклов и времена задаются при запуске. Программа должна показывать ход моделирования и причину завершения.

## Как устроено решение

Я использовал последовательную событийную модель. Программа работает в одном процессе. У каждого философа есть структура с его состоянием, временем следующего события и статистикой. Вилки хранятся в отдельном массиве: для каждой указано, кто ей владеет. Значение `-1` означает, что вилка свободна.

Философ может думать, ждать вилки, есть или уже закончить все циклы. При досрочной остановке незавершённые философы получают состояние «остановлен».

Для философа с индексом `i` нужны вилки `i` и `(i + 1) % N`. Остаток от деления нужен, чтобы последний философ был соседом первого. Внутри программы индексы начинаются с нуля, а в выводе номера начинаются с единицы.

Длительности размышления и еды выбираются случайно из заданных диапазонов. Параметр `seed` позволяет повторить тот же запуск.

## Как выдаются вилки

Голодные философы добавляются в очередь. Программа смотрит на первого, если обе его вилки свободны, он получает их и начинает есть. После этого можно обслужить следующего. Если хотя бы одна вилка занята, очередь ждёт следующего события.

Используется строгая очередь. При одновременном появлении заявок первым добавляется философ с меньшим индексом. Все философы используют один алгоритм.

Взаимной блокировки нет, потому что философ получает сразу две вилки. Ситуация, когда каждый держит одну вилку и ждёт вторую, здесь не возникает. Едящие философы заканчивают еду за конечное время и освобождают обе вилки.

Новые заявки добавляются в конец и не могут обогнать старые. Поэтому при продолжении моделирования каждый дойдёт до начала очереди. При этом заданный пользователем лимит ожидания может оказаться слишком маленьким, тогда программа остановится с сообщением об этом.

У такого решения есть недостаток: иногда свободные вилки простаивают, потому что первый в очереди ждёт занятую вилку, а следующие не могут его обойти.

## Время и порядок событий

Программа не перебирает каждую миллисекунду, а переходит к ближайшему событию. В один момент сначала обрабатывается окончание еды, затем окончание размышления, после этого проверяются лимиты и выдаются вилки.

Есть два ограничения: `max_wait` задаёт допустимое ожидание вилок, а `time_limit` общее модельное время. Ожидание ровно до `max_wait` включительно разрешено. Значение `time_limit=0` отключает общий лимит, но проверка ожидания остаётся. Если все циклы завершились ровно на общей границе, программа заканчивается успешно.

Параметр `display_delay` добавляет реальную паузу для просмотра событий. На модельное время он не влияет, и для быстрых проверок я задаю его равным нулю.

## Завершение и статистика

Обычное завершение происходит, когда каждый философ закончил нужное число циклов. При превышении лимита программа сообщает причину остановки. Также предусмотрена обработка SIGINT и SIGTERM, когда обработчик запоминает сигнал, а основной код освобождает вилки и печатает итоги.

Цикл засчитывается только после окончания еды. Если еда прервана, она не увеличивает число завершённых циклов. В статистике отдельно показываются ожидание перед начатой едой и ожидание тех, кто так и не получил вилки. Среднее ожидание считается по начатым приёмам пищи.

Вывод идёт в терминал и в `philosophers.log`. Неправильные параметры проверяются до начала моделирования, ошибки системных вызовов через `SOFT_ASSERT_ERR`.

## Проверка программы

Сборка и запуск тестов:

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Тесты написаны на C. В них программа запускается с разными аргументами, после чего проверяются код выхода и сообщения. Есть девять групп: справка, обычный запуск, несколько циклов, лимит ожидания, общий лимит времени, ошибки параметров, сигналы SIGINT/SIGTERM, запуск со 137 философами и порядок очереди.

Дополнительно тесты читают события выдачи и освобождения вилок. Проверяется, что занятая вилка не выдаётся повторно, философ начинает есть с двумя своими вилками, а в конце все вилки свободны. Для запуска с несколькими циклами проверяется результат каждого философа и повторяемость при одинаковом `seed`. Вывод сравнивается с содержимым лога. 

Для SIGINT и SIGTERM тест дожидается начала еды и отправляет сигнал. Проверяются код выхода, причина остановки, прерывание еды и освобождение вилок.

### Обычный запуск

```bash
./bin/philosophers 2 1 3 3 7 7 7 0 42
```

Оба философа думают 3 ms. Первый ест с 3-й до 10-й миллисекунды, второй - с 10-й до 17-й. Каждый завершает один цикл. Ожидания равны 0 и 7 ms, среднее 3,50 ms. Код выхода = 0.

### Слишком долгое ожидание

```bash
./bin/philosophers 2 1 0 0 200 200 150 0 42
```

Первый философ сразу начинает есть, второй ждёт. На 151-й миллисекунде ожидание превышает лимит 150 ms, и модель останавливается. Еда первого прерывается, завершённых циклов нет. Вилки освобождаются, код выхода = 2.

### Общий лимит времени

```bash
./bin/philosophers 2 1 0 0 200 200 1000 0 42 fifo 50
```

Модель останавливается на 50-й миллисекунде. Первый философ ещё не успел закончить еду, второй всё это время ждал. Обе вилки освобождаются, код выхода = 2.

Вывод этих трёх примеров сохранён в `tests/normal.log`, `tests/wait_timeout.log` и `tests/time_limit.log`.
